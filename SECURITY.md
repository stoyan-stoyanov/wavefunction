# Security

## Reporting a vulnerability

Report vulnerabilities privately through GitHub: on the repository's **Security** tab, choose **Report a vulnerability**. Please don't open a public issue for a security problem.

Include the affected version or commit, a synthetic reproduction, expected and actual behavior, and evidence without credentials or personal data. Do not publish secrets, application data, or unredacted logs. Fixes land on `main` and ship in the next release; only the latest release is supported.

## Security model

Wavefunction can edit code, run commands, call model providers and connectors, and operate an isolated computer. Prompts and skills are guidance. Enforced tool policies and the native macOS sandbox provide local boundaries.

The packaged API binds to loopback and requires a generated per-launch bearer token. Source development bypasses API authentication on loopback; do not expose it to a network. Credentials are app-local files with user-only permissions, not vault-encrypted. Hosted providers and connectors receive the inputs sent to them.

Code mode runs allowed project tools without action-by-action approval. Plan mode withholds mutation and command tools. Access outside the project requires a saved read-only or writable folder grant; writable grants cannot be requested from Plan mode. Grants can be revoked in Settings → Access. Commands remain sandboxed with network access enabled by default; an explicit offline choice in Settings → Access is honored. As in Codex, the agent can ask to run a command outside the sandbox, for what it blocks such as Docker; it runs after the user approves it on its card, with the user's environment minus the app's own variables. A chat with full access, turned on by the card's "Allow for this chat" or the chat's settings, runs those commands without asking, as Claude Code's bypass-permissions mode does; the composer shows it and turns it off. A command that can't be undone, such as a delete that the chat's code history can't restore, discarding uncommitted work, a force push, or deleting a database, Docker volumes or cloud resources, asks in every mode, full access included. A fixed check spots these, as in Codex and Hermes, so it catches an overeager agent rather than a determined one. `git` and `gh` reach GitHub through the app's proxy, which adds the sign-in on the way out, keeping tokens out of model inputs and results and SSH keys protected.

Project deletion exemptions require complete bytes in the existing pre-command capture; the presence of `.git` alone is insufficient. Unknown directories, globs, ignored data and uncaptured large files require approval. Generated dependency/build folders, task scratch and temporary folders remain disposable by policy. An outside-sandbox approval cannot authorize a newly irreversible command on replay: its current warning must have been shown and approved. Rewind restores the code saved at a message; it is not an archive of every intermediate version the agent creates.

The sandbox permits project/granted folders, task scratch, and the system/toolchain support needed to execute tools. Private application data and credential locations remain excluded. Commands that may use the network reach GitHub through the app, holding a placeholder rather than the GitHub CLI's token: the app adds the sign-in on the way out, so `git` and `gh` work as in the user's terminal while a script a command runs cannot read or send the token. The placeholder is new at each start and the app's GitHub listeners take only requests that carry it. A command can still act on GitHub as the user through them, as in other coding agents' terminals; pushes that delete branches or push tags are refused. Explicit `gh api` DELETE requests require command approval; this does not add a proxy API blocklist. The token is never written to Git configuration, specs or logs. A provider or connector enforces its own authorization. Version checks protect file saves and recovery from overwriting changes made since they were read.
